# thai-writing

English → [README.md](README.md)

สกิลป้ายบอกทางสำหรับเอเจนต์เขียนโค้ด AI ช่วยร่างและแก้ไขข้อความ **ภาษาไทย** ให้ถูกต้อง ทุกแนวงานเขียนและทุกชนิดไฟล์

เอเจนต์เขียนภาษาอังกฤษได้ดีอยู่แล้ว เพราะโมเดลถูกฝึกมาด้วย style guide ภาษาอังกฤษมาตั้งแต่ต้น ภาษาไทยไม่มีสิ่งนี้ ธรรมเนียมที่ผู้อ่านไทยซึมซับเป็นนิสัย — การเว้นวรรคทำหน้าที่แทนเครื่องหมายวรรคตอน ไม่จบประโยคด้วยมหัพภาค ไม้ยมก เลขแบบไหนที่ควรใช้ หนังสือราชการต้องมีรูปแบบอย่างไร — คือจุดที่โมเดลมักทำผิดครึ่ง ๆ กลาง ๆ สกิลนี้ไม่ได้สอนการเขียนใหม่ทั้งหมด แต่บอกให้เอเจนต์ใช้ style guide ภาษาอังกฤษที่ใช้อยู่แล้วสำหรับแนวงานนั้นต่อไป แล้วเติมเฉพาะส่วนต่างที่เป็นภาษาไทย ทุกส่วนต่างอ้างอิงแหล่งที่มาภาษาไทยเสมอ พร้อมมีตัวตรวจสอบแบบไม่พึ่งไลบรารีภายนอกสำหรับตรวจกลไกทางภาษา

## ตัวตรวจสอบ

```
node skills/thai-writing/scripts/check-thai.mjs <file>...            # รายงานผล จบด้วย exit 1 ถ้าพบ error
node skills/thai-writing/scripts/check-thai.mjs --genre gov <file>   # ปิดเสียง info เรื่องเลขไทย
node skills/thai-writing/scripts/check-thai.mjs --genre ui <file>    # ปิดเสียง NBSP; --fix จะเก็บ U+00A0 ไว้
node skills/thai-writing/scripts/check-thai.mjs --fix --write <file> # ซ่อมกลไกระดับ error แล้วเขียนทับไฟล์เดิม
```

กฎแยกตามระดับ

**ระดับ error** (ซ่อมอัตโนมัติได้)

- `ำ` ที่เขียนแยกเป็นสองอักขระ (`U+0E4D` `U+0E32`)
- จุดกว้างศูนย์ (zero-width space)
- NBSP
- BOM
- เครื่องหมายเต็มความกว้างที่หลุดมาจากแหล่ง CJK

**ระดับ warn** (ต้องใช้วิจารณญาณ อธิบายไว้ใน references)

- เว้นวรรคซ้อนสองครั้งขึ้นไป
- จบประโยคด้วยมหัพภาค
- การเว้นวรรคหน้า-หลัง `ๆ`
- การเว้นวรรครอบตัวเลขและคำละติน
- `;` กับ ` · ` ที่ใช้เป็นตัวเชื่อมกลางประโยค
- การเว้นวรรคหน้า `,` กับ `;`
- การเว้นวรรคหน้า `ฯ` กับ `ฯลฯ`
- อักขระ ellipsis (`…`)

**ระดับ info**

- เลขไทย นอกแนวงานที่ต้องใช้
- การเว้นวรรคหน้า `? ! :` — ราชบัณฑิตยสภาเว้นวรรคหน้าเครื่องหมายเหล่านี้ ขณะที่คู่มือผู้ผลิตซอฟต์แวร์และมหาวิทยาลัยที่สกิลนี้อ้างอิงส่วนใหญ่เขียนติดคำ จึงบอกไว้เฉย ๆ ไม่ตัดสินว่าผิด

ไม่มีการตรวจเครื่องหมายคำพูดปิด เว้นวรรคท้ายบรรทัดกี่ช่องก็ตาม (เป็น hard break ของ Markdown) ไม่ถูกตรวจ และ `--fix` ไม่แตะการเว้นวรรคเลย ซ่อมเฉพาะกลไกระดับ error ด้านบนเท่านั้น

แฟล็ก

- `--genre <name>` — `gov` ปิดเสียงเรื่องเลขไทย `ui` ปิดเสียง NBSP และให้ `--fix` เก็บ U+00A0 ไว้
- `--allow-ellipsis` — ยอมรับ `…` ในแนวงานที่ต้องใช้ เช่น Netflix subtitles
- `--plain` — ปิดการรับรู้ Markdown (fenced block กับ code span กลับมานับเป็นเนื้อความปกติ) ใช้กับไฟล์ `.txt` ดิบ
- `--json` — รายงานผลเป็นข้อมูลที่โปรแกรมอ่านต่อได้
- `--strict` — จบด้วย exit 1 เมื่อพบ finding ระดับใดก็ได้ที่ไม่ใช่ info ไม่ใช่แค่ error
- `--fix` — ซ่อมเฉพาะกลไกระดับ error ปล่อยรายการระดับ warn ให้คนตัดสินใจเอง
- `--write` — เขียนผลจาก `--fix` ทับไฟล์เดิมแทนการพิมพ์ออกหน้าจอ

exit code

- `0` — สะอาด ไม่พบปัญหา
- `1` — พบ finding ระดับ error (หรือพบ finding ที่ไม่ใช่ info เมื่อใช้ `--strict`)
- `2` — ไม่ส่งไฟล์มาเลย หรืออ่านไฟล์ไม่ได้

รับรู้ Markdown เป็นค่าเริ่มต้น fenced block code span และช่องว่างจัดตำแหน่งในตารางไม่ถูกนับเป็นเนื้อความ

ไม่พึ่งไลบรารีภายนอก ใช้ได้กับ Node.js 20 ขึ้นไป ทดสอบด้วยคำสั่ง `node --test test/check-thai.test.mjs` (ต้องระบุชื่อไฟล์ เพราะรูปแบบโฟลเดอร์ใช้ไม่ได้บน Node 24)

## มีอะไรอยู่ในนี้

- `skills/thai-writing/SKILL.md` — แกนกลางที่ใช้ทุกแนวงาน ตัวจัดเส้นทางไปยัง reference แต่ละแนว กลไกเฉพาะชนิดไฟล์ และรายการข้อห้าม
- `skills/thai-writing/references/` — ไฟล์สั้น ๆ หนึ่งไฟล์ต่อหนึ่งแนวงาน ได้แก่ `articles-news.md` `docs-readme.md` `government-legal.md` `ui-i18n.md` `subtitles-social.md` `fiction-translation.md` `academic-thesis.md` `channels.md` (ไฟล์นามสกุลเดียวแต่มีผู้ผลิตหลายราย เช่น `.docx` `.pdf` `.xlsx` `.pptx`) และ `transfer/en-to-th.md` (ตารางแปลงธรรมเนียมภาษาอังกฤษเป็นรูปแบบไทย) รวมถึง `sources.md` กับฉบับที่โปรแกรมอ่านได้ `sources.json` ซึ่งเป็นบรรณานุกรมที่ทุกกฎอ้างอิง
- `skills/thai-writing/scripts/check-thai.mjs` กับโฟลเดอร์ `test/` — ตัวเครื่องมือจริง

## แหล่งอ้างอิง

ทุกกฎอ้างอิงแหล่งที่มาไว้ที่ `references/sources.md` — สำนักงานราชบัณฑิตยสภา (การเว้นวรรค เครื่องหมายวรรคตอน การทับศัพท์) ระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ Unicode/UAX/CLDR และคู่มือภาษาไทยฉบับทางการของ Microsoft กับ Netflix กฎที่ถูกอ้างถึงบ่อยที่สุดคือการตัดมหัพภาคท้ายประโยค **ไม่ใช่** กฎของราชบัณฑิตยสภา หน้ามหัพภาคของราชบัณฑิตยสภาเองยังระบุว่ามหัพภาคเป็นเครื่องหมายจบประโยค แหล่งที่มาของการตัดมหัพภาคทิ้งคือคู่มือของ Microsoft และ Netflix (ดูเหตุผลใน `references/sources.md`) กฎที่ไม่มีแหล่งอ้างอิงจะกำกับด้วย ⚠️ house convention
